# プロトタイプの UX 試験 — 観点（指示書）

**誰が:** 議論していた人たち。お茶から戻って、スマホでプロトタイプを開く。
**何をしに来たか:** 「議論で決めたことを、明日から始められるか」を確かめに来た。
**見ていないもの:** コード・ログ・設定。**画面だけ**。

観点は Claude が決める。1つずつの操作と判定はローカルで回す（`teatime/uxcheck.py`）。
**判定は「動くか」ではなく「その人が使えるか」。**

## 機械で見る（Playwright）

| ID | 観点 | 合格 |
|---|---|---|
| M1 | **押して何も起きないボタンが無い** | すべての button / [onclick] / a を1回押し、DOM・入力値・表示のどれかが変わる。変わらないものを列挙 |
| M2 | **押した結果が逆になっていない** | 「編集」「保存」「追加」などの文言のボタンを押した直後、対応する入力が編集可能（disabled でない）か、一覧が1件増える |
| M3 | **空のまま押したら、何か言う** | 入力欄を空にして主ボタンを押す。何も変わらず、何のメッセージも出なければ不合格 |
| M4 | **決めたことを1件、最後までやれる** | 入力欄をすべて埋めて主ボタン → 一覧に入れた値が見える |
| M5 | **再読み込みで消えるかを、隠さない** | M4 のあとリロード。消えたなら「消える」と報告し、その旨がプロトタイプの仮置き一覧に載っているかを見る |
| M6 | **スマホ幅で読める** | 375×812 で横スクロールが出ない。押せる要素が 40px 角以上 |
| M7 | **仮置きの一覧が開いて閉じる** | `#fab` で `#sheet.on`、閉じるで外れる |
| M8 | **コンソールにエラーが無い** | pageerror / console.error の件数 0 |
| M9 | **古い日付・今日でない既定値が無い** | input[type=date] の既定値が空か今日 |

## ローカル LLM が見る（議論の中身に触れるので、外に出さない）

| ID | 観点 | 合格 |
|---|---|---|
| L1 | **議論に無い中身を作っていない** | 画面に見える文（例・候補・見出し）を、文字起こしと仮置き一覧と突き合わせる。どちらにも根拠が無い文を列挙。**仮置きに載っていない作り話は不合格** |
| L2 | **決めたことと矛盾していない** | 抽出の `decision`（採用・条件）と、画面がやらせていることが食い違っていないか。例:「案は次回出す」と決めたのに、案が画面に並んでいる |
| L3 | **最初の1手が分かる** | 開いて10秒で「何をすればいいか」が分かる見出し・文言があるか。1文で、その1手を書かせる。書けなければ不合格 |

## 出力
- `out/<stem>.ux.json`：ID ごとに `pass` / `fail` / `skip`、理由1行、根拠（セレクタや該当文）
- **fail の一覧だけ**を Claude が読み、直すか・仮置きに回すかを決める
