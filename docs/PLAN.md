## 1. 最高性能 — teatime が行き着く姿

### 一言で
**議論から戻った人が、自分たちでは見えていなかった「手放し続けている価値」を突きつけられ、
しかも翌日から決めたとおりに動ける形を手にしている。**

### それはどういう状態か（ここまで行けば最高）

| 層 | 最高の状態 | 測り方 |
|---|---|---|
| **1回の議論** | 放棄点（何を、何のために手放したか）を、参加者が「そう、それを捨てた」と認める精度で取る。理由が言葉になっていない放棄を見落とさない | 参加者による判定。取りこぼし／作り話の件数 |
| **成果物** | 4文書と動くプロトタイプが**議論に無いことを一文も足さず**、決めたことと**一度も矛盾しない**。仮置きは全部見える | UX 試験 L1（作り話 0）・L2（矛盾 0） |
| **最初の1手** | プロトタイプを開いて10秒で「明日何をするか」が分かる | UX 試験 L3、M1〜M9 全 pass |
| **回をまたぐ** | 10回分の放棄から、**その部屋が手放し続けている価値を1行で言い当てる**。言い当ては選別に使わず、ラベルとして見せる（「これは、この部屋が過去に3回捨てた方向です」） | 言い当てテスト（#7）。参加者が当たりと認めるか |
| **私的さ** | 録音も中身も手元から出ない構成が、スイッチ1つで選べる | `TEATIME_BACKEND=ollama` で外への通信 0 |
| **作り方の経済** | 品質を落とさずに、Claude の消費を最小にする。考える工程だけに Claude を使う | `task_tokens.py` の作業ごとの消費、委譲の判定 |

### 最高ではないもの（目指さない）
- **より多く記録する・より速く要約する。** 要約と議事録は**コモディティ**で、差別化にならない
- **好みに合わせて出すものを事前に絞る。** 過去の重心に収束し、taste が育たない（#8 の立場）
- **「全部できます」に見える画面。** 機能を並べても、使う人の手数は減らない

### いちばん外れやすい前提
**実際の議論で、まだ一度も使っていない。** 最高性能の上の3行は、全部この1回（#6）が無いと測れない。
**コードをどれだけ良くしても、#6 より先には進めない。**

## 2. 誰が、どんな場面で使うか

- **誰が:** サービス開発、または組織の改善を議論している2〜5人のチーム（最初は授業のチームと本人の身の回り）
- **場面:** 20〜30分の議論 → スマホで録音を止める → **席を外す（お茶）** → 戻って、できたものを品評する
- **見ているもの:** スマホの画面だけ。**端末・ログ・設定は誰も見ない**
- **来た目的:** 「決めたことを、明日から始められるか」と「自分たちは何を捨てたのか」を知ること

## 3. いまの形と状態

```
スマホで録音 → 文字起こし（uni2 の mlx-whisper, 10分ずつ）
            → 放棄点の抽出（Claude）
            → taste の抽出（`teatime/taste.py`。**決定論が本体で 0.05 秒**、モデルは2バッチだけ）
            → 4文書（Claude）
            → 仮置きの決定（Claude） → プロトタイプの画面（Claude） → JS（ローカル qwen2.5-coder）＋ node --check
            → 1枚の HTML
```

行き先は `teatime/model.py` の `route(role)` 1か所で決まる。`role="think"` は Claude、`role="code"` はローカル。

### 確認済み（実行して、生成物をディスクから読み直した）
- スマホ実機で録音 → 最後まで通った（52秒の録音まで）
- 「やめる」：録音中・処理中の両方。テスト用サーバーでの実行で、その回のファイルが 0 件になることを確認
- 工程ごとの振り分け（#12）：実データでプロトタイプが通り、JS は1回目で `node --check` を通過
- 私的モードでは、ローカルが落ちても Claude に退避しない（単体で確認）
- プロトタイプの画面を Claude に戻した版：作り話の例が「例」の印付き2件まで、古い日付なし
- **taste の抽出（`teatime/taste.py`）を実データ（31分・491発話）で通した。**
  一次資料24件・引用の原文照合は別スクリプトで数え直して**捏造0**。
  `序列の作り直し（rebuilt）が 0 → 1 件`。根拠は `[13:32] ひけらかすじゃないけど`
  → `[13:45] いわゆるマーケティング的な要素`（**改名句の有無で決まる決定論。モデルを使わない**）
- **時間反転の対照**を毎回走らせている。向きを見る検出器（制約の消滅・以前の肯定からの反転・
  改名つきラベル拒否）は **forward 2〜3 → reversed 0**。レジスタ衝突は 58 → 57 で落ちない＝形だけ
- **反転テストが機械で通った。** 持ち主の輪郭「便利な道具より、旅を喜んで自慢を後押しする相棒を優先する」
  の**反転を支持する引用が原文に実在**（`[05:46] 便利アプリみたいな感じ` / `[21:55] ツイートし忘れる`）。
  **争える＝一般論ではない**ので `generic_risk: false`。支持引用が無ければ輪郭は成果物に渡さない
- **一次資料が成果物に漏れていない。** 4文書を実際に生成し、検出器名・内部ID・指標を grep して0件

### 未確認（やったと言わない）
- 新しい3つ（進行表示・プロトタイプ・アーカイブ）と「やめる」を**スマホ実機で**通していない（#5）
- **30分の録音**を通していない。画面ロックで録音が止まるか、抽出が 900 秒に収まるか（#5）
- 実際の議論で使っていない（#6）
- **taste は1本の録音でしか測っていない。** 未知の議論での適合率は未測定
- **放棄点の抽出そのものが不安定。** 同じプロンプト・同じ入力で3回走らせて **4 / 5 / 5 件**
  （保存してある基準 `/tmp/real.extract.json` は 9 件）。**件数で良し悪しを判定できない**
- レジスタ衝突は被覆 19.4%（上限 0.20 で9件切っている）。**旧辞書の 16.0% より広く、絞りでは劣る**

### 作業ツリー
**未コミットの変更がある**（`git status` で確認）。どれも上の「確認済み」の中身。
Codex は**最初にこれを1コミットにまとめてから**作業を始める（下の T0）。

## 4. 守ること（破ったら差し戻し）

1. **録音・文字起こし・生成物（`out/` `samples/`）をコミットしない。読まない。** リポジトリは public で、中身は実際の議論
2. **私的モード（`TEATIME_BACKEND=ollama`）では、どの経路でも外部 API を呼ばない。** 退避先が外になる変更は禁止
3. **文書は議論に無いことを埋めない。**「未入力」と出す。プロトタイプの仮置きは必ず一覧に載せる
4. **ネットワークの公開設定に触らない。** tailscale の funnel / serve を変更しない。サーバーは 8777 で待つだけ
5. **宛先を直書きしない。** ローカル LLM と uni2 の宛先は `model.py` と `transcribe.py` の既存の仕組みを通す
6. **黙って退避しない、黙って失敗しない。** どの経路を使ったかを `model.label()` と画面に出す
7. 既存の書き方に合わせる：短い日本語コメント、**理由を太字**、依存を増やさない（標準ライブラリ優先）
8. **サーバーを勝手に再起動しない。** 本番（8777）は人が使っている可能性がある。試すときは空いている別ポートで（8778 は別のサーバーが使っている）

## 5. やること（順番どおり）

各タスクは **合格条件をコマンドで確かめ、その出力を報告に貼る**。「動くはず」は合格ではない。

### T0. 基準を作る
- 未コミットの変更を確認し、1コミットにまとめる（`docs/gallery-*.md` を含めるかは人に聞く）
- **合格:** `git status` がきれい。`python -m py_compile teatime/*.py` が通る

### T1. プロトタイプの UX 試験（#13）— **Codex トライアルの本題**
- 指示書は `docs/ux-viewpoints.md`（観点 M1〜M9、L1〜L3）
- `teatime/uxcheck.py` を作る。M は Python の Playwright（chromium、375×812）、L はローカル LLM（`role="check"` を `model.py` に足す。**常にローカル、退避しない**）
- 結果は `<stem>.ux.json`、標準出力には fail だけ
- **確かめは合成のプロトタイプ2つだけで行う**（問題入りと、問題なし）。`out/` は読まない
- **合格:** 問題入りで M1・M2・M3・M6・M9 が fail、問題なしで M1〜M9 が pass か理由付き skip。L1〜L3 が JSON に入る
- 参考: OpenCode に一度頼んだが、40分ファイルを作らずに止まった。**範囲が広すぎた可能性がある。M だけ先に出してよい**

### T2. 試験を処理の流れに入れる
- プロトタイプを作った直後に `uxcheck` を回し、fail の件数を成果物の HTML に出す（隠さない）
- **合格:** 合成データで処理を通し、HTML に試験の結果が出る

### T3. 長い録音に耐える（#5 の後半）
- 抽出の 900 秒の制限と、1時間の文字起こし（約2万字）を、合成の長文で確かめる。足りなければ分割の設計を**提案**する（実装の前に人に見せる）
- **合格:** 2万字の合成文字起こしで抽出が通るか、通らない理由と案が出る

### T4. 回をまたいで持つ（#1）— ここから先は**設計を人と決めてから**
- 放棄点を回ごとに並べられる置き場（SQLite を第一候補。置き場は Mac Studio、外に出さない）
- アーカイブに「この部屋が過去に何回、同じ方向を捨てたか」を**ラベルとして**出す（選別には使わない）

### T5 以降（人が #6 を済ませてから）
- 言い当てテスト（#7）、選別あり／なしの比較（#8）、リアルタイム版（#9）、動画（#3）、助言（#4）

## 6. Codex トライアルの評価

このトライアルで知りたいのは、**品質を落とさずに Claude の消費をどれだけ減らせるか**。

| 何を | どう測る |
|---|---|
| 品質 | タスクごとに `ok`（そのまま採用）／`fixed`（Claude が直した）／`redo`（やり直し）。`ocdverdict` と同じ形で記録 |
| 守ることの違反 | §4 の違反件数。**1件でもあれば、その範囲は渡さない側に戻す** |
| Claude の消費 | 点検にかかった Claude の呼び出し回数と重み付きトークン（`~/.hermes/scripts/task_tokens.py`） |
| 手戻り | 合格条件を満たすまでの往復の回数 |

**これまでの実測（各1件。まだ計測とは言えない。14件で判断する）**
- Claude の消費の約8割は、毎回の文脈の読み直し。出力は約2割
- Claude が自分で作った場合（約80行）と、OpenCode に任せた場合（約150行）で、Claude の消費はほぼ同じ（約22万と約27万）
- OpenCode のコードは設計どおりだった。穴は設計書の側にあった（私的モードの退避）
- ローカル LLM にプロトタイプの画面を作らせると、決めたことを落とした → 画面は Claude に戻した

**報告の形（各タスクの終わりに）:** 変えたファイル／合格条件のコマンドと出力／§4 に触れたか／分からなかったこと。500字以内。
